`POST /v1/embeddings` takes the standard OpenAI request body and returns the standard embeddings object. Vectors are served from your own fleet, on the same machines and by the same placement decision as a chat request.

```bash
curl -sS "$KIBBU_BASE_URL/embeddings" \
  -H "Authorization: Bearer $KIBBU_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "<an-embedding-model-id>",
    "input": ["first document", "second document"]
  }'
```

## Request

<ParamField body="model" type="string" required>
  An **embedding** model id from `GET /v1/models`. A chat model here returns `400 model_kind_mismatch`.
</ParamField>

<ParamField body="input" type="string | string[]" required>
  One string, or an array of strings. Arrays of token ids are rejected — send text.
</ParamField>

<ParamField body="dimensions" type="integer">
  Truncate the returned vectors. Models that cannot do this return `400 dimensions_not_supported_by_model`.
</ParamField>

<ParamField body="encoding_format" default="float" type="string">
  `float` or `base64`.
</ParamField>

<ParamField body="tier" type="string">
  Kibbu extension. Routing priority — embedding backfills usually belong in `batch`.
</ParamField>

## What you get back

Vectors come back **unit length**. Kibbu handles `dimensions` and `encoding_format` itself rather than passing them to the engine, so the same request returns the same answer whichever machine served it — and a truncated vector is re-normalised, because a prefix of a unit vector is not itself unit length.

## Each input must fit in one pass

An embedding is computed in a single pass. Unlike a chat completion it cannot be streamed or split across batches, so an input longer than the serving machine can process in one go fails outright rather than being truncated or chunked for you.

<Warning>
  That failure currently surfaces as a generic `502 upstream_error`, not as a validation error naming the length. If you are embedding text of unpredictable size, chunk it yourself rather than relying on the error to tell you which input was too long.
</Warning>

## Errors

| HTTP | `code` | Meaning |
| --- | --- | --- |
| `400` | `model_not_enabled_for_org` | The model exists but is not enabled for your organization. |
| `400` | `model_kind_mismatch` | A chat model was addressed at the embeddings endpoint. |
| `400` | `dimensions_not_supported_by_model` | `dimensions` is not supported here. |
| `502` | `upstream_error` | The machine failed to produce vectors — including when one input was too long to embed in a single pass. |
| `503` | `model_not_loaded` | No machine has the model warm yet. Retry shortly. |

<Note>
  Cross-encoder reranking is not served today. If you are building a retrieval pipeline, plan its second stage outside Kibbu for now.
</Note>
